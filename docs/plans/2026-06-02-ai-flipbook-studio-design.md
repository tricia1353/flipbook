# AI Flipbook Studio 产品设计

日期：2026-06-02

## 1. 产品方向

AI Flipbook Studio 是一个移动端优先的 PWA，用来让普通消费者自助制作 AI 翻页书礼物。用户可以上传自己的短视频，也可以上传本人、宝宝、恋人或宠物的参考照片/短视频，再通过模板和少量 prompt 微调生成 AI 短视频。系统最终把 3-5 秒的动态画面转成约 45-60 帧，制作成口袋礼物版实体翻页书。

第一版不做完整电商系统，而是做「自助创作 + 订单草稿提交 + 微信人工确认」。用户完成预览后提交微信号、手机号、收货信息和备注，由人工通过微信确认效果、价格、收款、制作和发货。

核心卖点：

> 把一段回忆，或者一个幻想场景，做成一本拿在手里会动的小礼物。

产品需要隐藏帧数、抽帧、AI prompt、视频处理、出血线、PDF 拼版等技术细节。用户只需要选择创作方式、上传或描述、确认预览、提交需求。

## 2. 目标用户

第一版面向购买个性化礼物的普通消费者，尤其适合：

- 情侣与纪念日礼物
- 宝宝成长与家庭纪念
- 宠物礼物
- 生日惊喜
- 旅行回忆
- 节日和表白场景

用户不需要懂剪辑，也不需要懂 AI。第一版最重要的成功标准是：用户是否能在约 5 分钟内完成一次创作，并愿意提交订单草稿。

## 3. 第一版商品规格

MVP 只支持一个固定 SKU：

- 规格：口袋礼物版翻页书
- 动态时长：3-5 秒
- 帧数：约 45-60 帧
- 履约：人工打印、裁切、装订、发货
- 支付：微信人工确认后线下收款

固定规格可以降低抽帧、打印排版、质量检查、报价和生产履约的复杂度。

## 4. 创作模式

App 有两个顶层创作入口。

### 4.1 上传视频做翻页书

用户上传一段自己的短视频，然后选择 AI 处理方式：

- **换个世界**：保留人物、宠物或主体动作，生成或替换 AI 背景。
- **变成电影/动画**：对整段视频做 AI 风格化。

「换个世界」模板示例：

- 童话森林
- 月球漫步
- 生日派对
- 复古街道
- 海边日落
- 奇幻雪景

「变成电影/动画」模板示例：

- 动漫
- 黏土
- 复古胶片
- 油画
- 童话绘本
- 赛博风

这个入口是成品稳定性最高的路径，因为动作来自用户真实视频，AI 主要负责增强想象力。

### 4.2 AI 生成我的幻想翻页书

用户上传本人、恋人、宝宝或宠物的参考照片/短视频，选择模板，再微调几个简单字段。系统生成 3-5 秒 AI 短片，并转换成翻页书。

模板示例：

- 我的宠物在月球奔跑
- 宝宝走进童话森林
- 情侣在复古电影街道相遇
- 生日祝福出现在魔法房间
- 宠物变成小英雄

用户不应该从空白 prompt 开始。每个模板背后都有结构化 prompt，只暴露少量可编辑字段，例如主角、场景、氛围、风格、祝福语。

## 5. 用户流程

1. 用户用手机打开 PWA。
2. 用户选择「上传视频做翻页书」或「AI 生成我的幻想翻页书」。
3. 用户选择模板并微调简单描述。
4. 用户上传所需素材。
5. 系统创建 AI 处理任务。
6. 用户看到清晰的生成进度和等待状态。
7. 系统生成最终短视频。
8. 系统抽取约 45-60 帧。
9. 用户通过拖动翻页和自动播放预览成品。
10. 用户提交微信号、手机号、收货信息、用途和备注。
11. 后台人工审核订单并通过微信联系用户。
12. 人工确认效果、价格和付款后开始制作。

## 6. MVP 范围

第一版必须包含：

- 移动端 PWA 创作流程
- 上传视频入口
- AI 生成视频入口
- AI 换背景模式
- AI 整段风格化模式
- 上传本人/宠物参考图或参考视频
- 模板 + prompt 微调
- 固定口袋礼物版规格
- 自动抽帧
- 翻页书预览
- 订单草稿提交
- 微信联系方式字段
- 简易后台
- 打印文件下载
- 人工履约状态管理
- AI 失败重试和人工兜底

第一版暂不做：

- 在线支付
- 用户账号系统
- 多规格商品
- 物流 API 对接
- 自动化打印工厂对接
- 高级视频时间线剪辑
- 单帧级手动编辑
- 优惠券、会员、分销
- 完整自动退款流程

## 7. 前端体验

第一屏应该直接进入创作，而不是做传统营销落地页。整体体验应该像一个轻量、温暖、好上手的移动端创作工具，用户一进来就知道可以「做一本会动的小礼物」。

建议页面：

- 创作入口页
- 模板选择页
- 素材上传页
- 描述微调页
- AI 生成进度页
- 翻页预览页
- 订单草稿表单页
- 提交成功页

翻页预览是建立信任的关键，需要支持：

- 拖动或滑动翻页
- 自动播放成短动画
- 展示当前模板和最终画面
- 提交前二次确认

用户界面不要暴露帧插值、mask、prompt token、PDF 出血等实现细节。

## 8. 后端架构

后端应该围绕异步任务设计。AI 视频生成、视频处理和打印文件生成都可能耗时较长，也可能失败，不能依赖同步接口完成。

推荐模块：

- Web App：移动端 PWA 和后台管理台
- API 服务：项目、订单、上传、任务接口
- 对象存储：源视频、参考图、AI 视频、抽帧图、打印 PDF
- 数据库：订单、项目、素材、模板、AI 任务、打印任务、管理员
- AI Worker：调用 AI 服务商并存储生成结果
- 视频处理 Worker：裁剪、统一画幅、标准化、抽帧
- 打印 Worker：生成可打印 PDF 或拼版图
- 后台管理台：审核、重试、下载、状态管理

AI 能力要通过 adapter 封装。产品内部调用 `generateVideo`、`replaceBackground`、`stylizeVideo` 这类能力，而不是把某个 AI 服务商写死在业务代码里。这样后续可以根据质量、价格、速度和可用性切换服务商。

- occasion
- user_note

- quoted_price

## 10. 后台操作台

后台第一版只需要服务人工履约，不需要做复杂 CRM。

主要视图：

- 按状态分组的订单列表
- 订单详情
- 项目素材查看
- AI 任务记录
- 打印文件下载
- 内部备注
- 状态更新

关键操作：

- 查看源素材
- 查看最终 AI 视频
- 查看抽帧图
- 下载打印 PDF
- 重新生成 AI 结果
- 重新抽帧
- 添加内部备注
- 标记已联系
- 标记已收款
- 标记制作中
- 标记已发货
- 取消订单

第一版可以只有一个管理员角色。等订单量上来后，再拆分客服、设计师、制作人员等角色。

## 11. AI 质量和兜底

AI 输出可能出现这些问题：

- 主体身份变化过大
- 人脸、手部或宠物形态扭曲
- 背景前后帧不一致
- 动作过于混乱，不适合翻页书
- 文字生成错误
- 画面太暗，不适合打印
- 主体被裁切

系统需要支持：

- 任务重试
- 后台重新生成
- 模板级 prompt 调优
- 基础画面质量检查
- 收款前人工微信确认

在 MVP 阶段，人工审核就是产品体验的一部分。系统不需要一开始就保证全自动生产。

## 12. 打印处理

打印 Worker 负责：

- 裁剪源视频到目标时长
- 统一口袋翻页书画幅
- 抽取约 45-60 帧
- 做基础亮度和清晰度检查
- 保证主体处在安全边距内
- 生成可打印 PDF 或拼版图
- 将打印文件保存为素材

MVP 不让用户选择帧数和尺寸，这些参数由固定 SKU 控制。

## 13. 推荐技术栈

建议第一版使用：

- 前端：Next.js + React
- 样式：Tailwind CSS 或轻量设计系统
- PWA：Next.js PWA 支持
- API：Next.js API routes 或独立 Node API
- 数据库：Postgres
- 文件存储：S3 兼容对象存储
- 队列：BullMQ、Inngest 或托管队列
- 视频处理：FFmpeg Worker
- 打印生成：服务端 PDF 生成
- 后台登录：MVP 简单邮箱密码登录

AI 服务商可以在实施阶段决定。架构上最重要的是保留统一 adapter 层。

## 14. 成功指标

建议跟踪：

- 创作开始率
- 上传完成率
- AI 生成成功率
- 平均生成耗时
- 预览完成率
- 订单草稿提交率
- 微信确认率
- 付费转化率
- 人工重做率
- 平均制作成本
- 到货后满意度

早期最重要的指标不是访问量，而是用户完成预览后愿不愿意提交订单草稿。

## 15. 迭代路线

### 阶段 1：原型

- 搭建 PWA 流程
- 做少量模板
- 跑通预览和订单提交
- 必要时允许人工处理文件

### 阶段 2：生产 MVP

- 接入异步 AI 任务
- 接入对象存储
- 增加后台操作台
- 增加抽帧和打印 PDF 生成
- 开始人工履约

### 阶段 3：商业化增强

- 增加在线支付
- 增加物流追踪
- 增加多规格商品
- 增加模板效果分析
- 优化 AI 服务商路由

### 阶段 4：规模化

- 增加用户账号
- 增加订单历史
- 对接打印工厂或生产 API
- 增加社交分享
- 增加创作者模板

## 16. 待决策问题

这些可以在实施计划阶段继续确定：

- 口袋翻页书的准确尺寸
- 最终帧数目标
- AI 服务商选择
- 对象存储服务选择
- 后端是全栈 Next.js 还是拆 API/Worker
- 后台登录方式
- 打印 PDF 拼版格式
- 没有账号系统时，用户是否可以保存未完成项目

## 17. 推荐下一步

下一步建议创建 MVP 实施计划，按以下里程碑推进：

1. 项目脚手架和移动端 PWA 外壳
2. 模板和上传流程
3. 翻页预览原型
4. 订单草稿提交
5. 后台操作台
6. FFmpeg 抽帧 Worker
7. 打印 PDF 生成
8. AI provider adapter 集成
